# 内容与代码评审：五项标准及规则案例

适用于课程实验、设计模式工作坊、章末评审和工程案例。前置是阅读对应需求并运行可运行部分；本标准不自动计入平台掌握度。返回 [规范索引](embedded-cpp-guideline-notes.md) 与 [内容总索引](../docs/content-map.md)。

## 五项人工评审

| 项目 | 0 分 | 1 分 | 2 分 |
| --- | --- | --- | --- |
| 正确性 | 正常路径也失败或执行 UB | 正常输入正确，边界覆盖不足 | 正常、边界、失败与状态转移都有行为证据 |
| 契约 | 输入、错误、时间或状态含糊 | 主要契约清楚，存在未声明边界 | 容量、单位、deadline、终态及错误原因明确 |
| 生命周期 | owner／借用或取消不清楚 | 常规路径可说明，关闭／失败未闭环 | 转移、取消、关闭及回调存活均可解释和验证 |
| 资源上界 | 无界分配、等待或重试 | 有预算，异常路径尚未覆盖 | 存储、队列、重试和等待在所有路径有界 |
| 验证证据 | 仅文字声称成功 | 有输出但环境或反例不足 | 固定版本、可重复命令、期望／实际和限制齐全 |

本仓库练习建议门槛：每项至少 1 分、总分至少 8 分。越界、未定义行为、生命周期悬空或未声明的无界等待必须先修复，不能用总分抵消。评审人记录依据；这不是已验证的通用能力量表。

## 重点规则：错误、推荐、检测和例外

| 规则 | 错误写法／设计 | 推荐 | 如何检测 | 例外需要什么依据 |
| --- | --- | --- | --- | --- |
| 数据所有权 | 把临时输入的 string_view 保存成“快照” | 明确借用期限或复制到有界自有存储 | 修改源缓冲区后检查保存内容 | 调用方确实活得更久，并写出失效时刻 |
| 容量 | 仅判断数据长度，遗漏 NUL 或元数据空间 | 明确容量单位，失败前不部分修改 | empty、min、max、max+1 与恰好可容纳 | 二进制 API 不使用 NUL，需在类型／文档声明 |
| 错误处理 | 对设备失败使用 assert 或统一返回 false | invalid、full、timeout、cancelled、transport error 分开 | 失败注入与错误传播检查 | 纯内部不变量允许 assert，但不能承担外部输入校验 |
| 生命周期 | 捕获 this 后立即销毁 owner | owner 覆盖完成处理，或取消并排空后销毁 | 析构计数、延迟完成、重复关闭 | 允许裸捕获时证明完成前 owner 不会退出 |
| 并发 | 以 shared_ptr／volatile 代替同步 | 显式执行上下文、锁或受支持的 atomic 协议 | 数据竞争工具、静态状态审查、调度对照 | 单线程／单 strand 也须禁止绕过上下文访问 |
| 超时／重试 | 每次 retry 都重新获得完整 timeout | 总 deadline 与最大次数同时受约束 | 可控时钟、边界时刻和重复发送次数 | 非幂等命令需显式去重／业务授权，不默认重试 |
| RAII 与上下文 | 析构隐式阻塞或在 ISR 调不合法 API | 声明释放上下文、阻塞上界与关闭动作 | 查析构调用链、关闭中取消实验 | 特定目标允许的 API 必须附版本和上下文证明 |

## 对照代码与检查方法

```cpp
// 仅示意规则，不是完整程序。
// 错误：异步保存的是借用，调用者可以先修改或销毁数据。
std::string_view saved = caller_buffer;
// 需快照时：检查长度后复制到固定容量存储；需借用时：声明完成前不可改／释放。
```

完整可运行例子见 [Modem 通道](../docs/engineering-learning-path.md)，不要将上面的片段作为独立 Lab。静态分析有助发现部分问题，但不能证明协议正确；sanitizer 通过也不证明所有调度顺序安全。
