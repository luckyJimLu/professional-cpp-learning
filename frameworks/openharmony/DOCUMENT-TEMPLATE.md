# OpenHarmony 轻量系统 · 文档模板与收录约定

返回 [模块首页](README.md)。复制下列结构创建专题文章，替换所有待填项后再标为已完成。
源码引用优先使用固定 tag 或 commit 的链接；行号与结论必须对应同一版本。

```markdown
# NN · 主题名称

## 目标与适用范围

- 本文解决的问题：待填
- OpenHarmony release/tag 与 manifest revision：待填
- 相关仓库 commit（如 kernel_liteos_m）：待填
- 内核、芯片架构、开发板及修订号：待填
- 主机系统、工具链与语言标准：待填
- 验证状态：资料整理 / 源码核对 / 仿真验证 / 板端验证（据实选择）

## 前置条件

所需硬件、软件、配置、权限和前置阅读。

## 概念与源码路径

解释接口契约与调用链；附固定版本的官方文档、源码路径和符号。
说明哪些是官方陈述、哪些是源码推导、哪些经过实验验证。

## 操作步骤

给出工作目录、完整命令、配置修改和必要文件，不依赖隐藏的 IDE 状态。

## 预期结果与失败分支

列出预期输出、实际观察、常见失败原因与定位方法。

## 资源与生命周期边界

说明 ownership、回调取消、任务/ISR 上下文、阻塞与 timeout、栈/堆/容量限制。
不涉及的项目写明不适用。

## 验收与回归

给出可操作的成功标准，以及与主题相关的错误路径和边界检查。

## 参考资料与验证记录

固定版本链接、核对日期、验证环境、实际结果及未验证部分。
```

引用外部代码和图片时保留来源与适用许可证信息。文章新增后更新 [模块首页](README.md)
和 [内容规划](ROADMAP.md) 的链接与状态。
