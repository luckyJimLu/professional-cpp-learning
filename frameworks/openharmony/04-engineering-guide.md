# 04 · 源码获取、接口选择与工程核对

返回 [模块首页](README.md)。本页为工程核对指南，尚不是已完成的开发板构建教程。

## 固定版本与资料复核

本次读取的是官方仓库 `OpenHarmony-v5.0.0-Release` 标签解析后的固定 commit。
[来源清单](sources.json) 对采集过的文档、头文件及关键实现记录 SHA-256。
原始检出和下载缓存存放在工作区 scratch，**不属于 Git 入库交付**；仓库内保存整理文档、
逐符号定位及可重新下载核对的来源清单。

复核单个文件时，从清单选择条目，用对应 `raw_url` 下载原始字节后比对 `sha256`。
来源链接已固定到 commit，不应改成浮动 `master` 后仍沿用旧的核对结论。
第三方原始文件版权和许可证以其仓库及文件头为准；本模块以整理和链接为主，没有整库复制官方资料。

## 完整系统获取与构建

本次未下载完整多仓库系统，也未设置目标板或执行 `hb build`。准备实验时：

1. 按对应版本官方《源码获取》准备 repo、依赖、网络和存储空间。
2. 通过官方 manifest 选择同一个 release，确认 `ohos:mini` 所需组及板级依赖。
3. 保存实际 `repo manifest -r` 输出，作为这次实验的完整源码锁定记录。
4. 按该版本、该板卡的官方指导准备工具链、选择产品并执行构建；不跨版本复制命令。
5. 保存产品配置、链接 map、固件 hash、构建日志、烧录参数、串口输出和验收结果。

单独克隆 `kernel_liteos_m` 无法补齐转发头依赖、产品配置和 BSP。不要因为某个头文件能被编辑器索引，
就声称完整工程已可构建。

## 选择接口层

| 场景 | 优先考虑 | 原因 / 后续核对 |
| --- | --- | --- |
| 应用线程、同步与消息 | 已验证的 CMSIS-RTOS2 子集 | 减少业务代码对原生内核的依赖；仍需检查适配限制 |
| 内核机制、资源诊断或特定功能 | 原生 LOS API | 契约与内核版本强绑定，放在较小的适配边界内 |
| 板级中断与外设 | 目标板 BSP 与该版本 IoT 接口 | 中断优先级、引脚和阻塞行为由底层实现决定 |
| 系统服务注册 | bootstrap + SAMGR Lite | 初始化顺序、对象寿命与消息所有权需要整体设计 |

同一资源从创建到释放保持同一套 API 协议。不能把 `osMutexId_t` 当作 `UINT32` 原生锁 ID，
也不能将 `osThreadId_t` 与 LOS task ID 直接强转互换。

## 任务、ISR 与 C++ 边界

- 优先把 ISR 做成“采集最少信息 + 发出允许的非阻塞通知”，把复杂处理转交任务。
- 共享缓冲区要定义写入、发布、读取、归还各阶段；`volatile` 不能提供完整同步协议。
- C++ 对象先确定 owner 和销毁顺序，再包装 OS 句柄；析构必须处理仍在途的任务与回调。
- 强制删除任务不会替应用做标准 C++ 栈展开。优先协作退出、等待完成，再释放句柄和借用对象。
- C 回调边界禁止异常跨语言传播；异常、RTTI、全局构造、标准库和堆策略以实际工具链配置为准。
- 上位机课程使用 C++23，不等于目标编译器/标准库支持全部 C++23；每个实验记录真实标准和库配置。

## 最小回归矩阵

| 领域 | 正常路径 | 必测边界 / 错误路径 |
| --- | --- | --- |
| 任务 | 创建、运行、协作退出 | 创建失败、栈水位、停止时仍有借用者 |
| 同步 | 加锁、解锁、唤醒 | 超时、锁顺序反转、重复释放、禁止的 ISR 调用 |
| 队列 | 入队、出队 | 满、空、超时、消息尺寸不符、指针载荷提前销毁 |
| 事件 | 单 bit、多 bit 条件 | 重复写合并、清除掩码、保留位、销毁时仍有等待者 |
| 内存 | 申请、使用、配对释放 | 池耗尽、对齐、越界、重复释放、碎片与水位 |
| 定时器 | 启动、触发、停止 | 回调超时、自动删除模式、取消时回调在途 |
| 外设 | 初始化、传输、退出 | 负返回/短读写、总线故障、Flash 越界、重启与掉电 |

这些是后续实验验收要求，当前没有把任何一项标为板端已通过。
