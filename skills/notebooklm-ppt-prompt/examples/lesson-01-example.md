主页：
1. 内存所有权（Memory Ownership）= 谁负责销毁对象
2. 非所有权（Non-owning）：只观察，不销毁、不延寿
3. 独占所有权（Exclusive Ownership）：不可复制，可显式转移
4. 共享所有权（Shared Ownership）：最后一个所有者释放资源
补充页（良好所有权设计的四大标志）：
1. 不改变所有权：调用者与实现者一目了然
2. 夺取独占所有权：接口强制客户端显式 move
3. 共享所有权：接口显式声明
4. 仅凭类型签名即可判断是否需要 delete

  · 独占所有权：单把钥匙图标；典型：栈变量、std::unique_ptr<T>
  · 共享所有权：多把钥匙/引用计数图标；典型：std::shared_ptr<T>

  对比表下方 2×2 网格列出"良好所有权设计的四大标志"。
- 高亮元素：在补充页底部用 #38BDF8 强调一句核心哲学："把所有权语义编码进类型系统（Type System），让编译器做生命周期检查"。

【6. 代码 / 表格（如有）】
左栏（❌ 原样保留）：
// ❌ 糟糕设计：所有权完全成谜，看代码上下文猜谜语
Widget* w = MakeWidget();        // 我需要 delete w 吗？用 delete 还是 free？
Widget* w1 = Transmogrify(w);    // w 被销毁了吗？还是悬空了？

右栏（✅ 对照写法）：
// ✅ 现代 C++：签名即文档
std::unique_ptr<Widget> MakeWidget();                       // 调用者获得独占所有权，自动释放
std::unique_ptr<Widget> Transmogrify(std::unique_ptr<Widget> w); // 夺取所有权，调用方必须显式交出
void Inspect(const Widget& w);                              // 非所有权：只观察
void Register(std::shared_ptr<Widget> w);                   // 共享所有权：显式声明

auto w  = MakeWidget();
auto w1 = Transmogrify(std::move(w));   // std::move 即"同意转移"，此后 w 不再拥有对象

【7. 演讲者备注（放入 Speaker Notes，不出现在幻灯片正文）】
传统 C++ 里内存泄漏、Double Free、野指针满天飞，根本原因真的是程序员记性差吗？不是。看左边这两行：拿到一个 Widget*，我要不要 delete？用 delete 还是 free？传给 Transmogrify 之后 w 还活着吗？Widget* 这个类型承载了太多模糊的语义，你只能翻上下文、翻文档去猜。
在 C++ 里，内存所有权其实就是对象所有权：谁负责管理这个对象的生命周期并最终销毁它。只有三种状态：非所有权，只看不管；独占所有权，一个人全权负责，不能复制但可以显式转移；共享所有权，大家平等共有，最后一个离开的人关灯。
现代 C++ 的核心哲学，是把这些语义编码进类型系统。看右边：签名本身就说清了一切，std::move 就是客户端签下的"同意转移"。我们不再写"Please do not delete"这样的注释，而是让编译器替我们做静态检查。那么类型说清了"谁负责"，"什么时候释放"又靠什么保证？这就是下一页的 RAII。
