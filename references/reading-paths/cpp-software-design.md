# C++ 入门与软件设计：四阶段参考书导读

先建立值语义、确定性析构和所有权的心智，再学习如何设计接口与组织变化。不要把主要依赖引用对象与垃圾回收的语言经验直接套入 C++；也不必把继承、虚函数视为应当一律消除的机制。根据变化方向、生命周期、可测试性和实测成本选择组合、运行时多态或泛型。

## 四阶段路线总览

| 阶段 | 前置条件 | 阅读目标 | 实践产出 |
| --- | --- | --- | --- |
| 1 · 夯实基础 | 会写基本程序 | 类型、值语义、资源和对象寿命 | 一个使用容器与 RAII 的小程序 |
| 2 · 现代惯用法 | 理解构造、析构和引用 | 接口契约、推导、移动、智能指针 | 所有权图与异常安全说明 |
| 3 · C++ 原生模式 | 能区分拥有与借用 | 根据变化选模式，对比动态与静态多态 | 同一需求的简单基线与两种方案 |
| 4 · 性能与重构 | 能说明模式的收益和代价 | API/ABI、编译依赖、策略组合与测量 | 含证据的重构记录 |

与[底层机制路线](cpp-compiler-abi.md)互补：本页回答“如何设计”，另一篇回答“编译器怎样实现”。不必读完编译器源码才开始软件设计。

## 第一阶段：体系化入门与快速进阶

### 《C++ Primer》第 5 版

Stanley B. Lippman、Josée Lajoie、Barbara E. Moo 著，内容以 **C++11** 为基础。适合作为体系化主线与查阅资料；注意它不是《C++ Primer Plus》。

已有 C 基础时，重点读第 7 章类、第 12 章动态内存、第 13 章拷贝控制、第 15 章面向对象编程、第 16 章模板与泛型。遇到引用、表达式或容器使用不熟，再回到相应基础章节。

要建立的区别：对象与裸存储、拷贝与共享、移动与销毁、拥有与借用。新手业务代码优先使用容器和智能指针，不把书中的 new/delete 机制示例直接变成默认编码风格。

### 《Essential C++》

Stanley B. Lippman 著。适合已有编程经验者先建立过程式、基于对象、面向对象、泛型编程的整体地图，再回 Primer 补细节。

本书属于较早的 C++ 时代，不能独自承担现代智能指针、移动语义和 C++20 的学习。读到旧接口或资源管理写法时，记录其意图，再对照现代替代方案；不以书的篇幅或固定天数作为掌握标准。

### 《A Tour of C++》第 3 版（《C++之旅》）

Bjarne Stroustrup 著，覆盖至 **C++20**，并涉及部分后续发展。适合已有基础者快速校准现代语言全貌；快速导览不替代逐项机制训练。

重点观察 Concepts 如何表达模板约束、Ranges 如何组合算法、Modules 如何组织接口，再回顾容器、资源管理与错误处理。模块能否直接编译取决于工具链和构建系统，不能只看 -std=c++20。

**实践与检查点：** 写一个读取文本、统计结果的小程序，用 string/vector 管理存储，用 RAII 管理文件。能解释对象何时销毁、返回值是否拥有数据，以及失败路径是否泄漏，才进入下一阶段。

## 第二阶段：从语法走向现代惯用法

### 《Effective C++》第 3 版

Scott Meyers 著，主要基于 **C++98/03**。读接口设计、资源管理、构造析构、继承与替代方案；将旧时代代码与现代语言规则分开。

NVI（非虚接口）可让公开入口维护契约，再通过虚函数提供变化点；组合、函数对象与策略也可能更合适。书中的 TR1、auto_ptr 等历史内容需用当前标准库与所有权设计重新审视，不能原样用于现代项目。

### 《Effective Modern C++》

Scott Meyers 著，面向 **C++11/14**。重点读模板/auto 推导、智能指针、移动与转发、lambda 捕获和生命周期。

std::move 只是转换，不保证发生移动；std::function 是类型擦除包装，可能分配且常有间接调用。把调用方、被调用方、回调捕获对象的存活关系画清楚，再讨论 Strategy 或 Observer。

**实践与检查点：** 给一个接口标出输入、输出、拥有、借用和可空性；构造一个异常/提前返回路径，解释资源为何仍能释放。若无法解释捕获 this 的回调何时悬空，先完成寿命练习再增加模式。

## 第三阶段：从 GoF 到 C++ 原生设计模式

### 《设计模式：可复用面向对象软件的基础》

Erich Gamma、Richard Helm、Ralph Johnson、John Vlissides（GoF）著。以 23 种模式的意图、适用性、协作关系和后果建立共同语言，原书示例使用 C++ 与 Smalltalk。

阅读顺序可从 Strategy、Factory、Adapter、Observer 开始，再按问题补其他模式。理解“针对接口编程”的解耦意图，但接口不一定要表达为继承层次。GoF 也重视对象组合，不能将它概括为只会堆虚函数。

### 《C++ Software Design》

**书名：** *C++ Software Design: Design Principles and Patterns for High-Quality Software*。**作者：** Klaus Iglberger。

先读设计原则、职责与依赖关系，再阅读与当前问题有关的模式。重点不是记住类图，而是识别真正会变化的部分、隔离变化，以及比较运行时多态和编译期多态。

重点主题：值语义、非侵入式设计、Strategy、Bridge、Visitor 与类型擦除。把同一需求分别用直接组合、虚接口和模板实现，记录新增一种行为时需要修改哪些模块。

**实践：** 为“日志格式化与输出”拆开两个变化维度。先写最小直接组合版本，再引入策略；说明新增文件输出、JSON 格式分别影响什么。只有当扩展或测试确有收益时才增加抽象层。

**检查点：** 能回答“为什么采用这个边界”和“什么时候不用这个模式”，并指出额外分配、间接调用、编译依赖与测试替身的成本。

重点对比运行时多态与模板/约束，研究 std::variant + std::visit 的封闭类型集合、函数对象策略与类型擦除。variant 访问未必没有分支，静态多态可能增加代码体积；类型擦除可提供不要求用户类型继承的外部接口，但内部仍可能使用虚函数或间接调用。

中文版可按《C++软件设计：设计原则与模式实战》检索，具体出版信息以所持版本版权页为准。

### 《Design Patterns in Modern C++20》第 2 版

**作者：** Dmitri Nesteruk。第一版书名为 *Design Patterns in Modern C++: Reusable Approaches for Object-Oriented Software Design*。第二版改名为 *Design Patterns in Modern C++20: Reusable Approaches for Object-Oriented Software Design*。

**版次说明：** 当前 Drive 文件版权页为 2018 年第一版，电子 ISBN 978-1-4842-3603-1。没有将它标为 C++20 第二版；第二版书名作为选读信息列出，暂不提供未经核对的第二版文件链接。

已有第一版先看引言的 SOLID，再按创建型、结构型、行为型问题查阅。Builder/Factory 用于构造问题，Adapter/Bridge 用于接口与变化隔离，Strategy/Observer 等用于行为替换和通知；不要为了套全模式而堆叠继承层次。

**实践：** 实现一个可取消订阅的事件通知器。说明订阅者销毁、回调期间退订、异常、重入及并发各自的契约。先解决单线程寿命，再决定是否引入同步；观察者模式本身不提供线程安全。

**检查点：** 能说明模式解决的具体变化，给出不使用模式的简单基线，并指出例子中的教学简化与项目所需的错误处理之间的差距。

第二版可作为现代代码驱动的模式手册，与现有第一版对照阅读。不要假定每个模式都必须用协程、CRTP 或某一个 C++20 特性重写；以实际目录与示例为准。

**阶段检查点：** 对同一需求同时保留直接组合的基线、动态接口方案和一种泛型/值语义方案，比较扩展方向、测试难度、编译依赖与运行成本。虚调用不必然导致堆分配或指针碎片化，这些还取决于存储设计。

## 第四阶段：性能、API 与重构实战

### 《Hands-On Design Patterns with C++》第 2 版

**书名：** *Hands-On Design Patterns with C++*，第 2 版。**作者：** Fedor G. Pikus。资料库版权页明确标注第二版于 2023 年 6 月出版，ISBN 978-1-80461-155-5。

按现有第二版目录，先读第 1–3 章：继承与多态、类/函数模板、内存与所有权。接着读第 4–6 章：swap、RAII、类型擦除；后续模式按实际问题选读。

把“使用某个模式”转成可检查的对象契约：谁拥有资源？能否复制？移动后有什么保证？异常发生时是否泄漏？借用视图何时失效？类型擦除对象怎样复制和销毁？

**实践：** 给回调容器先选择 std::function，写出捕获对象寿命和复制约束；再研究小对象优化及移动专用回调的需求。不要为了模仿库实现，直接把未完成异常安全和对齐处理的自制包装投入生产。

**检查点：** 能解释为何 RAII 不只管理内存，swap 与异常安全有何关系，类型擦除与虚继承分别如何隔离类型，以及性能比较需要什么基准条件。

进一步研究 CRTP、策略与并发设计时，先确认运行时是否需要开放扩展。CRTP 可避免某些虚派发，但不意味着整个程序无运行时成本。类型擦除的小缓冲优化通常称 SBO/SOO；SSO 通常指 small string optimization（小字符串优化），两者不要混称。

并发模式要分别证明对象寿命、数据竞争与进展保证：线程安全不等于无锁，无锁也不保证每次操作等待有界。性能结论需记录负载、编译选项、平台及基准方法。

### 《C++ API设计》（API Design for C++）

Martin Reddy 著。把视角从类推进到模块、库与 SDK，重点阅读稳定接口、头文件依赖、Pimpl、二进制兼容、回调与插件边界。不同版次的语言覆盖范围不同，按主题查阅。

Pimpl 可隐藏布局并减少编译依赖，但可能增加分配与间接访问；它不自动保证全部 ABI 兼容。还要检查导出符号、调用约定、异常边界、分配/释放是否跨运行库，以及插件卸载后是否仍有回调或对象存活。

**实践：** 为一个小库发布 v1 接口，随后仅改变内部成员；保留旧客户端，检查重新链接或直接替换库时的适用条件。把源兼容、二进制兼容和行为兼容分别记录。

### 《C++设计新思维》（Modern C++ Design）

Andrei Alexandrescu 著，以 **C++98 时代**的泛型与编译期设计为背景。重点理解基于策略的设计、类型列表和行为组合；用变参模板、类型特征与 Concepts 重新表达选定例子。

策略模板可把部分选择移到编译期，不会彻底消除运行时开销：分配、I/O、算法工作量、缓存失配仍然存在，也可能换来更多实例化和代码体积。将其作为架构思想训练，不必照搬历史工具链的技巧。

**阶段检查点：** 提交一份可复核的重构说明，包含简单基线、变更需求、异常/寿命契约、编译或 ABI 影响，以及实测数据。没有证据时描述假设，不把模板、无锁或零开销作为结论。

## 两条务实阅读路线

**日常开发与重构：** A Tour of C++ 第 3 版 → Effective Modern C++ → C++ Software Design → 按问题选读 Pikus 第 2 版和 API Design for C++。每次以一个真实模块为对象，优先学习类型擦除、Pimpl、策略和所有权的取舍，不要求先读完整个书单。

**扎实打底：** C++ Primer 第 5 版 → Effective C++（结合现代规则校正）与 Effective Modern C++ → GoF 的意图/后果 → C++ Software Design。已有经验但缺整体地图时可先读 Essential C++；用 A Tour of C++ 补现代全景。

两条路线最终都应回到值语义、资源安全和可验证的工程效果。可从[设计模式专题](../../patterns/README.md)和[工程选型工作坊](../../patterns/engineering-workshop.md)展开练习。
