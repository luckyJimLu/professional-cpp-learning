# C++ 新手入门：先跑通，再理解，再修改

这里的“新手”包括刚接触编程，以及会写 C、但不熟悉现代 C++ 的读者。两者都从自己的薄弱环节开始，不要求先理解 Modem、RTOS 或所有设计模式。课程已发布不等于你已经掌握；以可解释、可运行、可修改的证据为准。

## 先选适合自己的入口

| 你的情况 | 从哪里开始 | 暂时不必做什么 |
| --- | --- | --- |
| 不会编译运行，也不熟悉变量、函数 | 下面的工具步骤，再从 Day 1 开始；变量是保存值的对象，函数是一段可调用的处理过程 | 不必先安装交叉编译器或连接板卡 |
| 会写 C，但不熟悉引用、标准库和生命周期 | Day 1–6，重点比较按值、借用、边界与类型 | 不必立刻重写原有工程 |
| 会写基础 C++，开始学习类 | 先自测 Day 4、5、17，再进入 Day 28–31 | 不必先掌握复杂多继承或 mixin |
| 能写类，准备学习内存管理 | 先完成 Day 31，再按 Day 56–64 顺序学习 | 不必直接从 PMR 或对象池开始 |

## 第一步：认识文件、命令与结果

源码是你编辑的文本，编译器把源码变成程序，运行才执行程序。修改 `.cpp` 后，旧的可执行文件不会自己更新。

1. 准备仓库副本，在终端进入仓库根目录；这里应能看到 `daily/`、`examples/`、`README.md`。编辑器用于修改文件，终端用于输入命令，两者不是同一件事。
2. 若在 Linux／WSL 等提供 GCC 的环境运行，先执行 `g++ --version`，确认编译器存在并支持本课所需标准库。C++23 的开关不保证每个版本都实现了全部库功能。
3. 在网页的「课程」打开 Day 1，先找到对应 `main.cpp`；也可使用「实验」中的浏览器编译器。浏览器不能替代真实网络、线程、设备或板端验证，支持范围见环境矩阵。
4. 主机命令示例中的 `/tmp` 面向 Linux／WSL。Windows 用户可先用 WSL 或浏览器实验，不要把 Linux 路径直接当成 PowerShell 路径使用。

在仓库根目录逐行执行：

```bash
g++ -std=c++23 -Wall -Wextra -Wconversion -Wpedantic -Werror examples/day-001/main.cpp -o /tmp/cpp-day-001
/tmp/cpp-day-001
```

第一行是**编译**：`examples/.../main.cpp` 是输入，`-o` 后面是输出文件。只有编译成功，才执行第二行。第二行是**运行**：预期输出 `signal sum=12`。这里 3、4、5 是写在程序里的输入，不要求你在终端键入它们。

- `#include <array>`：让编译器看到标准库数组的声明；不是把它下载到电脑。
- `int main()`：本例程序的入口；到达函数末尾等价于返回 0。
- `{3, 4, 5}`：三个初始值；此处花括号参与初始化，不是额外的执行步骤。
- `std::array<int, 3>`：保存三个整数的固定大小容器，元素个数属于类型信息。
- `const ...&`：借用已有对象并限制经这个引用修改；Day 4 会系统说明。
- `for (const int signal : signals)`：依次取数组中的每个值；不是无限循环。
- `assert(total == 12)`：检查总和是否符合实验预期。`==` 是比较，`=` 是赋值。
- `std::cout`：向标准输出写内容；`'\n'` 是换行字符。输出文本是可观察结果，不是函数返回值。

先照着现有代码理解，不必第一天记住所有符号。第一轮只需知道数据从哪里来、函数如何处理、结果在哪里检查。

## 第二步：做一个能预测的小修改

1. 保留原版，把最后的 5 改成 6。
2. **先写预期**：3 + 4 + 6 = 13，因此断言和输出应对应 13。
3. 把相关断言同步改为检查 13，重新编译，编译成功后再运行。
4. 对比实际输出；若还显示 12，先检查是否运行了旧程序、是否保存文件以及是否编译成功。
5. 还原或保存自己的实验副本。不要为了让测试通过删掉断言，也不要运行悬空指针、越界或重复释放的负例。

这里不要直接把长度改成 4 或 0：`Sum` 的参数写的是 `std::array<int, 3>`，其他长度不能直接传入。改变接口属于后续学习，不是本课“增加一个数字”就能完成的操作。

## 第三步：按八个阶段学习，而不是从头抄到尾

| 阶段 | 第一轮要做什么 | 交付什么 |
| --- | --- | --- |
| ① 阅读 | 看“解决什么问题”与前置链接 | 用自己的话说出今天的问题 |
| ② 回忆 | 先回答上一课问题 | 记下一处还不理解的地方 |
| ③ 概念 | 读两个白话术语，再跟踪一次执行 | 输入 → 处理步骤 → 结果 |
| ④ 对照 | 看旧写法的具体问题，不只背“现代写法更好” | 一个收益和一个适用限制 |
| ⑤ 规范 | 找到规范保护的错误或维护风险 | 规则对应的代码位置 |
| ⑥ 实验 | 先原版，再只改一个变量或条件 | 命令、预期、实际和差异 |
| ⑦ 常见坑 | 对照自己是否有同类误解 | 一个反例或边界条件 |
| ⑧ 自测 | 解释、修改、辨析；最后才展开答案 | 能说明原因的答案 |

原有 60 分钟是主线安排，不是新手必须跟上的速度。新增导读与拓展可分两次学习；遇到前置知识空缺，先回到对应 Day。主机实验通过只证明该输入与环境下的行为，不证明板端实时性。

## 不同阶段先抓什么

- **Day 1–7：** 变量、函数、基本类型、引用、范围和简单状态。先会运行与检查，不急着讲复杂架构。
- **Day 8–12：** 文本是谁的、视图借用谁、输入如何解析。先保证生命周期与边界，再谈减少复制。
- **Day 13–18：** 名字、单位、头文件、错误与控制流。先让调用者少猜，再追求工具自动化。
- **Day 19–27：** 需求 → 契约 → 最小实现 → 正常／失败测试。先画一条数据路径，不堆类图。
- **Day 28–40：** 有效对象、组合、拥有与借用，再进入多态。多继承与 mixin 留到基础例子能解释后。
- **Day 41–55：** 用真实变化学习复用与 SOLID。若普通函数或组合已满足需求，不引入模式也可以是正确答案。
- **Day 56–64：** 值与 RAII → 唯一所有权 → 共享生命周期 → 资源策略 → 原始存储。对象池不替代基础所有权训练。

## 遇到问题，先分清是哪一类

| 现象 | 先检查什么 | 不推荐的做法 |
| --- | --- | --- |
| `g++: command not found` | 环境是否安装了编译器，或改用支持的浏览器 Lab | 把源码内容粘到终端当命令 |
| 找不到源码／头文件 | 当前目录、文件名大小写、直接包含的头文件 | 盲目删除 include |
| 不认识 `std::format` 等库接口 | 编译器和标准库版本、该课环境要求 | 仅反复改 `-std` 开关 |
| 类型不匹配／窄化转换 | 两边类型、值范围、函数声明 | 用任意强制转换压掉错误 |
| `assert` 失败／程序中止 | 预期是否随输入变化更新，实际状态是否正确 | 删除断言或加 `-DNDEBUG` |
| 程序没输出 | 是否本来只用断言检查，退出状态是否成功 | 把所有无输出都当作失败 |
| 网页实验失败、主机可运行 | 浏览器是否支持异常、线程或所需库功能 | 声称任意嵌入式目标都支持该特性 |

## 怎样使用你现有的资料库

先读每日课里的“对照现有资料库”，只查当前问题：

1. 类型、命名、错误与资源规则：看 [嵌入式编码规范](../guidelines/embedded-cpp-guideline-notes.md)。它是项目工程建议，不是 C++ 标准全文。
2. 类的协作与释放责任：看 [所有权与智能指针](../patterns/ownership-and-smart-pointers.md)。先读 required/optional borrow，再读 shared ownership。
3. 是否需要设计模式：看 [模式选型工作坊](../patterns/engineering-workshop.md) 的“无模式基线”，不要从背模式名开始。
4. 学完生命周期再看 [Asio Session](../frameworks/asio/SESSION_LIFECYCLE.md)。异步取消、回调完成与对象释放是不同事件。
5. [迁移资料导读](reference-reading-guide.md) 保留来源版本、命名空间和适用环境。中英文资料是对照，不用重复学两遍，也不要跳过前置直接照搬生产代码。

资料中的性能结论、API 行为和平台支持都有环境前提。遇到差异时记录原路径、版本、现象和验证过程，不改写受校验保护的原始迁移资料。
