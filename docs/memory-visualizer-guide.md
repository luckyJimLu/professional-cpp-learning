# 内存可视化：5 条轨迹与生命周期检查题

前置：指针、作用域、RAII 和基本容器。返回 [内容总索引](content-map.md)。轨迹来自 `public/traces/`，预置快照是教学示意；实际 Clang VIS 事件与近似推演要按工作台标签区分。

## 实验流程

先读源码并标出 owner、borrower 和失效点，再逐步观察栈、堆与箭头。每步用一句话解释“谁发生了什么变化”。导出轨迹时记录它是预置、真实运行事件还是近似模型，不用示意地址证明真实 ABI。

## 1. unique_ptr 独占与转移

基线为 5 个快照：进入 main → make_unique → move → 检查空源指针 → 退出并释放。

- **预测题**：`std::move(p1)` 表达式自己会转移对象吗？p2 接收前后的 owner 分别是谁？
- **答案**：`std::move` 是值类别转换，接收方的移动构造／赋值实施转移。此例移动后的 p1 为空，p2 取得所有权，堆对象不因这次指针移动而搬家。
- **错误对照**：保存 `p1.get()` 的裸别名后，转移 owner 不会自动更新或删除这个别名；owner 最终释放时它可能失效。不要实际解引用失效别名。
- **验收**：解释一次对象析构、两个智能指针状态及借用的终止时刻，而不是只指出箭头变色。

## 2. shared_ptr 引用计数

5 个快照展示强拥有者计数 1 → 2 → 1 → 0。

- **预测题**：最后一个强拥有者释放时，对象和控制块一定同时释放吗？复制智能指针会使对象内部数据线程安全吗？
- **答案**：对象在强拥有者归零后销毁；仍有 weak_ptr 时控制块还需保留。当前例没有额外弱观察者，图中的合并块仅是该例的表现。共享生命周期不等于同步对象数据。
- **错误对照**：两个独立 shared_ptr 从同一个裸指针构造可能形成两个控制块；循环强引用可能阻止释放。本页不运行这类错误源码。
- **验收**：区分 owner 数、对象状态和控制块寿命；不要把 `use_count()` 作为跨线程业务同步协议。

## 3. 单链表反转

6 个快照显示三个节点从 1→2→3 变成 3→2→1；游标 prev、curr、nextTemp 按步变化。

- **预测题**：先改 curr->next 再保存 nextTemp 会丢失什么？head 改变时节点是否重新分配？
- **答案**：若没保存后继，可能失去尚未处理的链；本例只重连指针，没有以反转为理由分配新节点。
- **错误对照**：成环与失去最后一个可达 owner 是不同问题；“画完反转”也不等于演示了所有节点最终释放。
- **验收**：逐轮写出三个游标与已反转／未处理链，另说明清理责任。末帧不是程序退出或泄漏检测的证明。

## 4. vector 扩容与借用失效

4 个快照使用 capacity 1→2→4 的增长示意，以及三个管理指针的常见实现表示。

- **预测题**：这是否意味着标准规定 vector 必须两倍扩容、必须由三个裸指针组成？此前取出的引用何时失效？
- **答案**：两者都不是通用标准保证。发生重新分配时，旧存储上的指针、引用与迭代器失效；没有重新分配时仍要按具体操作检查失效规则。
- **对照实验**：原生小程序中记录 size、capacity 与 data 地址，比较先 reserve 和不 reserve 的 push_back。只比较地址数值，不解引用已经失效的指针；结果附标准库版本。
- **验收**：把标准保证、当前实现观察和预置示意分开写。用 reserve 预留不能替代正确的借用生命周期设计。

## 5. 悬挂指针与局部置空

5 个快照：创建对象 → delete → 保留旧地址 → 风险提示 → 当前指针置空；越界或 use-after-free 语句保持未执行。

- **预测题**：`ptr = nullptr` 能清空其他别名吗？可以修复已经发生的非法访问吗？
- **答案**：只能改变这个指针变量；其他别名、已排队回调或视图不随之改变。置空不能逆转先前的错误，通常应从 owner 与借用契约修复。
- **错误对照**：释放后仍访问是悬挂访问；遗失释放责任是泄漏，二者可以独立存在。预置标题不是实际泄漏检测结果。
- **验收**：画一个含两个别名的对象图，指出每个别名何时失效；提出 unique_ptr、外部 owner 或取消／排空协议中的一种可验证方案。
