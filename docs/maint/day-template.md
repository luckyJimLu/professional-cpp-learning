# 每日课程模板（Day Template）

所有 `daily/day-XXX-*.md` 必须遵循本模板。确保每篇课程在结构、篇幅与语气上保持一致；网站渲染依赖正文八阶段结构，课程元数据依赖 `lessons.meta.json`（见内容契约）。

---

## 课程元数据（daily/lessons.meta.json，必须）

`daily/*.md` 只写正文，**不再携带 frontmatter**。新课程的元数据追加到 `daily/lessons.meta.json` 的 `lessons` 数组（与正文同时提交）：

```json
{
  "path": "daily/day-017-errors-assert-control-flow.md",
  "week": 3,
  "part": "I",
  "chapter": 3,
  "chapter_title": "Coding with Style",
  "title": "Errors, Assert and Clear Control Flow",
  "duration": 60,
  "status": "published",
  "topics": ["error-handling", "assert", "control-flow"],
  "guidelines": ["no-assert-for-recoverable-errors", "early-return"],
  "lab": "examples/day-017/main.cpp",
  "previous": 16,
  "next": 18
}
```

约束：

- `path` 与 md 文件名一一对应；每个 day 文件必须恰好有一条条目。
- `previous` 为前一天编号，首课填 `-1`；`next` 允许指向尚未发布的后一天。
- RTOS 模拟课程：`lab` 填 `"rtos-sim"`，另加 `"rtos_scenario": "<id>"`。
- 可选字段：`date`（发布日期）、`patterns`（设计模式标签数组）。

## 正文结构（固定 8 节 + 下一步）

| 节 | 标题 | 时长 | 内容要求 |
|----|------|------|----------|
| ① | 今日章节与建议阅读范围 | 5 分钟 | 书的章节定位；今天只解决哪一个问题（用引用块强调）；重点关注 bullet 5~8 条 |
| ② | 昨日复习 3 问 | 5 分钟 | 恰好 3 个问题，源自上一天内容；建议先口头回答 |
| ③ | 核心概念 | 12 分钟 | 分 3~5 个小节讲透；每个概念配"为什么"和嵌入式视角 |
| ④ | C 写法 vs Modern C++ | 8 分钟 | 先给 C 风格代码 + 它的真实问题（bullet）；再给 Modern C++ 版本 + 好处；最后给"不要过度"的提醒 |
| ⑤ | 今日编码规范 | 8 分钟 | MUST / SHOULD / AVOID 三级条目，每条一句话 + 一行解释 |
| ⑥ | 可编译实验 | 15 分钟 | 实验目标、关键代码片段、编译运行命令、预期输出；完整代码在 `lab.path` |
| ⑦ | 3 个常见坑 | 3 分钟 | 恰好 3 个，每个：加粗标题 + 2 行解释 |
| ⑧ | 检查题 | 4 分钟 | 2 道题（Q1/Q2），每题有代码或场景；文末给"答案要点" |
| — | 下一步 | — | 一句话预告下一天主题 |

## 写作规范

- 标题：`# Day 17 · 中文标题`
- 代码块一律 ` ```cpp `，遵循仓库编码规范基线：
  类型/函数 `PascalCase`，变量/参数 `snake_case`，成员 `snake_case_`，
  常量 `kPascalCase`，`enum class`，RAII，`[[nodiscard]]` 优先。
- 嵌入式视角：每节至少一处点出资源/实时性/无异常语境下的取舍。
- 中英混排时，英文术语用反引号或加粗，不要裸奔。
- 禁止事项：不以投递、排版或迁移说明替代教学正文；
  实验代码必须在本地 `g++ -std=c++23 -Wall -Wextra -Wconversion -Wpedantic`
  下零警告编译并运行通过。


## 内容与验证附卡

保持上面的八阶段、lessons.meta.json 元数据和约 60 分钟结构；以下信息放在阅读、实验和检查题中，不创建另一套前端必须解析的字段。

- 阅读开头：本课一个核心问题、两至三个可观察学习目标、前置 Day／专题。
- 实验开头：源码路径、语言标准、依赖与运行环境；使用 [环境卡](../lab-environments.md) 记录版本。
- 实验结尾：正常、边界和失败输入；预期结果与实际结果分开；资源释放、容量、timeout 和上下文约束。
- 检查题答案：结论、依据、常见误答及可验证方法；设计题按 [评审标准](../../guidelines/review-rubric.md) 评分。
- 验证记录：资料／源码／主机／模拟／板端分别标注；未运行不填通过。专题和模拟器不等同于每日课程完成。
- 导航：至少关联一个已存在的前置内容及一个对应实验；后续尚未发布课程只给主题，不生成失效链接。

## 新手友好的逐课要求

参照 [新手入门手册](../beginner-start.md) 和 [逐课导航](../beginner-course-map.md)，在八阶段内补充解释，不新增前端依赖的元数据：

- ① 先用两三句话解释今天解决的具体问题，链接已发布的前置 Day。面向零基础读者的第一课先说明如何编辑、编译和运行。
- ③ 先定义两三个本课术语，再沿本课真实 `main.cpp` 的输入、调用、状态变化与结果逐步解释。不得把“抽象更好”“更安全”等口号当作解释。
- ⑥ 原版先运行；给一个只改变单一条件的小练习，并说明可预测结果或验收依据。编译失败和断言失败的负例要隔离并在解释后还原，禁止要求执行未定义行为。
- ⑧ 设置理解、应用、辨析三个层次，给出本课特有的辨析答案；仅能输出正确结果不代表掌握。
- 给出两处相关的现有资料库入口并解释用途。进阶资料不自动成为本课前置；标准语言规则、工程建议、来源版本与主机／板端证据要分开。
- 原约 60 分钟仅指主线，新增导读和拓展不虚报时长，允许分两次学习。已有短片段可以不完整，但围栏不可拆断，完整实验须有可运行源码。

## C++ 标准版本标注

正文或配套示例引入新特性时，明确其首次标准化版本（如 C++11、C++17），后增成员单独标注。完成后运行 `python3 tools/annotate-cpp-standards.py` 更新课首表；尚未收录的特性须先核对来源并补充识别规则。参见 [标准来源速查](../cpp-feature-standards.md)。
