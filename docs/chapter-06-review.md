## 任务：可取消的 Modem 通道

需求：调用者提交短命令后立即复用输入缓冲区；通道容量有限；请求可能成功、超时、被取消或遇到传输失败。关闭后不得接受新请求。第一版只有主机 Fake Transport，不要求动态注册、线程池或真实 UART。

先写出以下内容，再进入 [贯穿实验](engineering-learning-path.md)：

1. 哪个对象拥有请求字节？Transport 是借用还是拥有？谁必须活得更久？
2. 容量满、无效输入、超时、取消和设备失败分别如何返回？
3. 请求何时释放容量？取消已进入传输的请求与取消排队请求有何不同？
4. 测试如何不依赖真实 sleep？截止时刻恰好完成时采用哪条规则？
5. 为什么第一版可能不需要 Factory、Strategy 或 `shared_ptr`？

## 答案要点与常见误答

| 问题 | 合格答案依据 | 常见误答 |
| --- | --- | --- |
| 复用与抽象 | 抽象隔离真实变化，保留使用者需要的容量、timeout 和错误语义 | “增加虚基类就可复用” |
| 所有权 | 通道复制固定长度 payload；借用 Transport，通道先销毁 | “用了 span 就获得数据所有权” |
| 扩展方式 | 先直接组合；出现多个实现且需运行时替换时再考虑接口 | “所有依赖一律 shared_ptr + Factory” |
| 错误模型 | 正常运行中可发生的错误显式返回；断言只保护内部不变量与测试 | “外部输入不合法就 assert” |
| 时间模型 | 主机用可控单调时钟；真实目标映射时钟源并验证溢出／精度 | “sleep 10ms 后一定完成，所以没超时问题” |
| safeguard | 队列、重试、等待和日志都有预算；保护代码自身也不能无界运行 | “失败后一直重试直到成功” |

要求把答案对应到代码行、用例或明确的设计约束，不能只写术语。

## 设计变更评审

- **变化 A：加入串口与 TCP。** 如果不同构建选择不同实现，先比较模板／直接组装；同一进程运行时切换时再评估小接口或 Strategy。
- **变化 B：加入指标。** 优先外层记录或组合，不把日志、重试、协议解析全部塞进 Transport。
- **变化 C：多个请求并发。** 当前单活动请求的假设失效。先定义同步、响应关联、取消、顺序和关闭协议，再选择并发工具。
- **变化 D：禁堆目标。** 固定容量只是起点；还需检查标准库实现、栈、回调存储、日志和运行时初始化。
