# 专题

专题是不占用 Day 编号的深挖内容，每篇解决一个具体问题：读一份源码、验证一个模型、拆解一个平台。正文与可编译实验放在同一目录，读完能跑。

## 目录命名

```text
topics/<领域>/<主题>/README.md   # 正文
topics/<领域>/<主题>/lab/        # 可编译实验（可选）
```

- **领域**用英文小写单词，表示知识大类；已在内容管道登记中文名的领域会直接显示为分类。
- **主题**用英文小写 + 连字符，写“读者要解决的问题”，不写序号、版本或日期。
- 一个目录只放一个主题；实验代码放 `lab/`，保证 `-Wall -Wextra -Wconversion -Wpedantic` 通过。

| 领域目录 | 展示分类 | 适合的内容 |
|---|---|---|
| `stdlib/` | 标准库实现 | 容器、智能指针、分配器、迭代器的库实现 |
| `language/` | 语言语义 | 对象模型、重载决议、模板推导、ABI |
| `concurrency/` | 并发与内存模型 | 原子操作、内存序、线程同步原语 |
| `embedded/` | 嵌入式与系统 | RTOS、启动流程、链接与内存布局 |
| `tooling/` | 工具链与性能 | 编译器、调试器、性能分析、构建系统 |

新增领域时在 `scripts/build-content.py` 的 `TOPIC_DOMAINS` 登记中文名；未登记则直接显示目录名。

不要用 `topic-001`、`v2`、`new` 之类的名字：编号会随增删失效，版本和日期属于正文内容，不属于路径。

## 写作要求

1. **先给结论，再给依据。** 开头说明这篇解决什么问题，正文只保留读者需要的事实与最小必要源码片段。
2. **源码结论绑定版本。** 引用实现细节时写清仓库、commit/标签和符号名，并说明哪些是标准保证、哪些是该实现的策略。
3. **不写过程材料。** 设计讨论、迁移记录、覆盖率统计、内容规划不进入专题目录；正文只保留读者需要的知识、操作与结论。
4. **实验只验证可观察行为。** 不把内部布局、偏移或内存序当作标准承诺来断言。
